# Changelog

All notable changes to `yuanmaharsyah/admin-core` are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the package uses [SemVer](https://semver.org/).

## [Unreleased]

## [1.0.0] - 2026-10-29

### Added
- `make:module` field type `year`: an `unsignedSmallInteger` column, validated `between:1900,2100`, shown without a thousands mark in the list, detail and form (`NumberField` `grouping={false}`; `formatNumber()` takes `useGrouping`), real years in the factory. The `Sample` golden module uses it.
- Published as `yuanmaharsyah/admin-core` on Packagist (MIT): `LICENSE`, Packagist metadata (keywords, homepage, support), a package README that points to the main repository; private forks over SSH documented there.
- New projects start with `composer create-project yuanmaharsyah/admin-skeleton my-app`; `bin/release` publishes the skeleton to `yuanmaharsyah/admin-skeleton` with every release.
- Package scaffold: Testbench test suite on in-memory SQLite, Pest 5 with arch hygiene rules, Larastan level 8 (no baseline) and Pint with strict types.
- Package auto-discovery (`AdminCoreServiceProvider`) and `config/admin-core.php`.
- Module registry (`Yuan\AdminCore\Registry`): discovers the core and project module roots, validates every `module.php` (spec §3.1), fails boot on duplicate slugs or names, registers module providers, migrations and routes (`/admin/{slug}`, `{slug}.`, configured base middleware; `superadmin_only` routes require `admin-core.superadmin`).
- `admin-core.modules.disabled` turns off non-core modules of the core root.
- `modules:cache` / `modules:clear` (hooked into `optimize` / `optimize:clear`) and `modules:list`.
- `PageResolver`: `{Name}::{Page}` from `resources/js/pages` (case-exact), `App::` pages, `admin-core.pages.overrides`, and `viteEntry()` for `@vite` preloading; `resolvePage()` for the client.
- `MenuBuilder`: grouped, ordered, permission-filtered menu (`MenuGroupData` / `MenuItemData`).
- `admin:doctor`: npm dependencies against `admin-core.npm.json`, module cache state, environment sanity.
- Dependencies: `laravel/framework ^13.0`, `inertiajs/inertia-laravel ^3.0`, `composer/semver ^3.4`, `spatie/laravel-data ^4.23`, `spatie/laravel-typescript-transformer ^3.3`.
- Shared Data objects (`#[TypeScript]`): `AuthData`, `UserData`, `MenuGroupData`, `MenuItemData`, `AppData`, `FlashData` (native Inertia flash), `PaginatedData<T>` with `PaginationMetaData` / `PaginationLinksData`; `PaginatedData::fromPaginator()` keeps the query string.
- `Http\Middleware\HandleInertiaRequests`: shares `auth`, `menu`, `app` as Data objects; projects extend it to add props.
- `UPGRADE.md` with the standard upgrade steps.
- Audit core (`Yuan\AdminCore\Audit`, spec §7.1): `AuditEvent` taxonomy (labels, badges, fixed log names); `Audit::record()`, `Audit::batch()` (shared `batch_uuid`, nested batches join the outer one) and `Audit::actingAs()` (explicit causer for jobs); `LogsModuleActivity` model trait with `auditLabel()`; `AuditContext` (web / cli / queue); `Masker` with `admin-core.audit.masked_fields` (omit / partial / full) applied to `attribute_changes` and `properties`; append-only `ImmutableActivity` (`ImmutableAuditException`); auth listeners for `login`, `logout`, `login_failed`, `login_locked`, `password_reset`.
- Core migration `create_activity_log_table` (spatie v5 columns + `batch_uuid` + indexes); projects don't publish the spatie stub.
- `ModuleRegistry::forClass()` and `ModuleDefinition::customActions()` / `STANDARD_ACTIONS`.
- Dependency: `spatie/laravel-activitylog ^5.1`. The package forces its activitylog settings (activity model, write action, no buffering, default log name `system`).
- RBAC core (`Yuan\AdminCore\Permissions`, spec §6): `Level` (spatie Role with `label`, `description`, `is_protected`; `Level::superAdmin()`), `HasLevel` user trait (`assignLevel()` with a batched `level_changed`, `level()`, `isSuperAdmin()`; `assignRole` / `removeRole` / `syncRoles` / `givePermissionTo` / `syncPermissions` throw), `PermissionSynchronizer` + `permissions:sync`, `PermissionMatrix` (build, save with the dependency rule, one batched `permissions_updated`, `LevelPermissionsUpdated` event), `GuardRailViolation`.
- Guard rails: always ≥1 active Super Admin; the protected level is immutable; a level with users can't be deleted (checked before spatie detaches anything).

### Changed
- `AdminCoreSeeder`: a new Operator level gets `dashboard.view` and the `view` permission of the project's own (non-core) modules only, never Users, Levels or the activity log (was every `view` permission). Existing levels are never changed by a re-seed.
- The package is renamed `yuanmaharsyah/admin-core` (was `yuan/admin-core`, whose Packagist vendor belongs to someone else): it installs under `vendor/yuanmaharsyah/admin-core`. The PHP namespace `Yuan\AdminCore` is unchanged.
- `make:module` / `make:widget` messages and descriptions name the Boost skills (`admin-audit`, `admin-relation-field`…) instead of DEVELOPER.md recipes, which projects don't have.
- The package config is merged deeply under the project's `config/admin-core.php` (was Laravel's top-level `mergeConfigFrom`): a published file keeps every nested default it doesn't set, so nested keys added by later versions arrive. Associative arrays merge; lists (`routes.middleware`, `attachments.mimes`, `rules`, `modules.roots`) are replaced whole. A project therefore adds or overrides settings tabs, fields and menu groups but can no longer drop a default one by leaving it out.
- Breaking: files are uploaded with the record's form (`files.{slot}` in the input Data, `AttachmentUploads::saveWith()`), not one by one to `{slug}.attachments.store`: that route, `UploadAttachmentData`, `HasAttachments::attachmentRules()` and the `FileUpload` component are gone. `AttachmentsData` is now `slots: AttachmentSlotData[]`. `AttachmentController::routes()` no longer needs `edit` (the delete route is added only when the module declares it). Models without `attachmentSlots()` get one `lampiran` slot with the old limits.
- `admin-core.routes.home` is gone: error pages, the password change and sign-in go to `/home` (set Fortify `home` to `/home`). The starter kit's `/dashboard` route and page are removed.
- `admin-core.maintenance_banner` (`ADMIN_MAINTENANCE_BANNER`) and `AppData.maintenance_banner` are replaced by Settings → Akses Situs and `AppData.site_access`.
- `StatTile` `icon` also takes a lucide name; `SegmentBar` takes an `action` beside its title.
- `ModuleExport` now extends `ListExport` (same constructor, `row()` and formula-safe `map()`); `ExportManager::for()` accepts any `ListExport`.
- `ConfirmDialog` `processing` is now `confirmDisabled` (it only ever disabled the confirm button); `DataTable` `bulkDelete` receives an `onFinish` callback; `StaleUpdateDialog` `onReload` receives one too (`useAdminForm().reload(onFinish?)`).
- Projects' `App\Models\User` now extends the core User model, and the starter kit's settings profile page, its FormRequest and `Account\PasswordController` are replaced by the core account pages (`AccountRoutes::register()`).
- `Trash::delete()` reports the rows it actually deleted (a model whose `delete()` is refused isn't counted or offered for undo); nothing deleted flashes the error "Tidak ada data yang dihapus." instead of a success toast.
- `AdminCoreSeeder` sets `must_change_password` on the seeded Super Admins outside the `local` and `testing` environments.
- `ModuleRegistry::forClass()` also matches a model's parent classes, so a project model that extends a core module's model belongs to that module.
- Login accepts a username or an email in one field (`AuthenticateUser::credentials()`); the failed-login audit resolves the account the same way.
- `module.php` `icon` must be a lucide icon name from `resources/icons/lucide.json` (was: any kebab-case string).
- Base admin route middleware is now `web, auth, active`; superadmin_only modules use the `superadmin` middleware instead of `can:admin-core.superadmin`.

### Fixed
- Pengaturan: after a save the tab's form stayed "unsaved" (a leave-page warning for changes already saved) and kept the old `lock_version`, so a second save on the same tab without reloading failed as a stale update (409). The form now starts over from the saved values.
- Generated Wayfinder files named the package by its absolute path when `vendor/yuanmaharsyah/admin-core` is a symlink (the boilerplate repo), so they differed per machine; after every `wayfinder:generate` the package rewrites them to `vendor/yuanmaharsyah/admin-core/…` (`Console\WayfinderPaths`), as a project with the package installed gets anyway.
- Shell: on a page taller than the window (the Log Aktivitas), the window itself scrolled and left an empty band under the shell: the charts' screen-reader tables are absolutely positioned and had no positioned ancestor inside the scrolling main area. `<main>` is now `relative`.
- The audit summary and cached Beranda widgets failed on a real cache store ("__PHP_Incomplete_Class returned"): Laravel's `cache.serializable_classes => false` lets no object come back from the cache. Both now cache the Data's array form and rebuild it. The test suites' array cache serializes like a real store, so object caching fails in tests too.
- Shell: following a one-item rail group's link to the page already open (e.g. Keuangan on `/admin/invoices` after viewing Master Data) left the panel showing the other group; the link now clears the viewed group, the overlay panel and the mobile sheet.
- `LogsModuleActivity` no longer stores attributes with an `encrypted` cast; the trait read them decrypted, so they reached `attribute_changes` in plain text.
