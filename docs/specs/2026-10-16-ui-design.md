# Admin Boilerplate — UI Design Spec

- **Status:** Approved v1
- **Date:** 2026-10-16
- **Audience:** **UI/UX model only.** Coding agents must not read this file. They implement from `docs/design-implementation/*.html` + `docs/specs/2026-10-16-frontend-behavior.md`.
- **Output:** static HTML mockups in `docs/design-implementation/` (see §0).

Layout: **collapsible icon rail + command palette**, shadcn/ui style. The UI language defaults to Bahasa Indonesia and the target users are office/government operators. The UI aims to be predictable and dense, not decorative.

---

## 0. HTML Output Requirements (for the UI model)

The coding agent converts these files into React + shadcn/ui components. Follow these rules so the conversion is mechanical:

1. **One file per screen or component**, named exactly as listed in `docs/design-implementation/README.md` (e.g. `shell.html`, `users-index.html`, `levels-permission-matrix.html`).
2. **Tailwind 4 utility classes only** (CDN in `<head>` is fine), no custom CSS files.
3. **Colors only through the tokens in §1.2**, copied verbatim into each file's `<style>` (both `:root` and `.dark`):
   - Use the token names exactly as listed, including the non-shadcn ones: `--highlight`, `--rule`, `--rail`, `--sidebar-*`, `--chart-*`, `--success`, `--warning`, `--info`.
   - Use them as `bg-[var(--card)]`, or through a Tailwind theme mapping.
   - **No raw hex values in markup.**
   - Include a `.dark` variant of the same variables.
4. **Every state on the same page, stacked as labelled sections:** default, loading (skeleton), empty, empty-with-filters, error, a validation-error form, a permission-limited view (buttons hidden), and the dialogs that screen uses (confirm delete, stale update, unsaved changes).
5. **Mark components** with `data-component="DataTable"`, `data-component="PageHeader"`, etc., using the names in §5. Mark permission-gated elements with `data-can="users.create"`.
6. **Fixed sample data:**
   - App name **SIMANDA**, subtitle "Sistem Informasi Manajemen Data", organisation "Instansi Contoh".
   - Indonesian names, dates as `16 Okt 2026`, currency as `Rp 1.250.000`.
   - Never real institutions, NIK or personal data.
7. **Show widths** of 1280px, plus 375px for shell, index and form screens.
8. **No JavaScript logic** beyond toggling visible states for review. Behaviour is specified separately and implemented by the coding agent.
9. **Accessibility:** semantic elements (`nav`, `main`, `table`, `button`, `label for`), visible focus styles, `aria-label` on icon buttons.

## 1. Visual Language

**Design source:** `docs/design-implementation/reference/style-reference-01/`, the owner's original design work for this project (`index.html`, `users-index.dc.html`, `auth.dc.html`, `screenshots/app.png`). It ranks above this spec on looks (see `docs/design-implementation/README.md`); the tokens below were reconciled with it on 2026-10-19 and match it.
- **Take from it:** spacing and proportions, type sizes and weights, the card, table and KPI-tile anatomy, the ink rules, the density.
- **Map its values onto the token names below;** never paste raw `oklch()`/hex values or its CSS variables into components.
- **Ignore its JavaScript entirely.** Behaviour is defined elsewhere, and its demo only toggles states for review.
- **Don't carry over its class names, libraries (jQuery, Chart.js, icon fonts, etc.) or markup structure.** Mockups use Tailwind utilities + lucide icons as in §0.
- **Don't copy** its workspace switcher, General/Project toggle, branding, images or content.

**Reference style:** editorial monochrome. Neutral grays, near-black ink, one yellow highlight, flat surfaces, thick ink rules under titles, small uppercase labels and large numbers. Calm and dense, with no decoration.

| Rule | Value |
|---|---|
| Surfaces | Flat. **No shadows** on cards. Floating layers use the shadow tokens only: `--shadow-popover` (menus, popovers, chart tooltips), `--shadow-dialog` (dialogs, command palette), `--shadow-sheet` (mobile rail sheet), `--shadow-drawer` (side drawers). Modal layers sit on `--overlay` |
| Borders | 1px `--border`. Cards are separated by background contrast, not heavy borders |
| Title rule | 2px `--rule` (ink) line under the page title (full content width) and under card titles |
| Radius | `--radius: 0.25rem` (almost square). Pills (badges, avatars, status dots) are fully round (`rounded-full`); chart bars round only their top corners (2px) |
| Type | **Geist** (sans) and **Geist Mono** (codes, IDs, technical values at 13px), both self-hosted through `@fontsource-variable/geist` and `@fontsource-variable/geist-mono`; fallbacks `Inter, system-ui, sans-serif` and `ui-monospace, monospace`. Numbers use `tabular-nums` everywhere (tables, KPIs, money) |
| Scale | Named steps (Tailwind `text-*` theme sizes, which carry their line-height and weight; components use the names, never raw pixels): **`title`** 28px/700, line-height 1.15 (page title) · **`section`** 20px/700 (section and drawer titles, stat-stack values) · **`kpi`** 22px/700 (KPI values) · **`card-title`** 18px/600 (card, dialog and empty-state titles) · **`brand`** 18px/700, line-height 1.2 (app name) · body 14px, line-height 1.5 · table 13px · **`label`** 12px/500, letter-spacing 0.04em, uppercase (never smaller than 12px) |
| Control heights | Named theme sizes (`h-*`), never raw pixels: **`control`** 36px (default button, input, icon button) · **`control-sm`** 32px · **`control-compact`** 30px (toolbar buttons) · **`control-auth`** 40px (auth primary button) · **`row`** 44px (table row) · topbar 48px |
| KPI tile | Icon (20px, ink) top-left → uppercase label → value 22px/700. Tiles sit on `--card` over the `--background` page |
| Icons | lucide-react, 16px in tables/buttons, 20px in rail/KPI. Ink color; the active rail group icon sits on a yellow square |
| Spacing | 4px scale with 2px half-steps allowed (6, 10, 14px: Tailwind `1.5`, `2.5`, `3.5`); page padding 32px desktop / 16px mobile; card padding 24px |
| Breakpoints | `sm 640`, `md 768`, `lg 1024`, `xl 1280`. Rail + panel become a sheet below `lg` |
| Formatting | `id-ID`: `16 Okt 2026`, `16 Okt 2026 13:40`, `Rp 1.250.000`, `1.250,5` |
| Accessibility | WCAG AA text contrast (4.5:1), 3:1 for UI shapes, visible ink focus ring (2px, offset 2px), keyboard-reachable, `aria-label` on icon buttons |

### 1.1 Color Roles

| Role | Used for | Never used for |
|---|---|---|
| **Ink** (`--primary`) | Primary buttons, title rules, focus ring, checked controls, chart series 2 | Large background areas |
| **Yellow** (`--highlight`) | Active rail group, active-state markers, chart series 1, "new" indicators | Text, buttons, status, thin lines, hover backgrounds |
| **Neutrals** | Everything else (≈90% of any screen) | — |
| **Status** (success/warning/info/destructive) | Status badges, alerts, destructive buttons only | Categories, decoration, chart series |

Yellow fails text contrast on light backgrounds. It may only fill large shapes (≥ 24px tall), and always next to or labelled with ink.

## 3. Page Anatomy

Every page follows the same pattern:

| Page | Structure |
|---|---|
| **Index** | PageHeader (title, description, `+ Tambah` if create) → Toolbar (search, filter chips, column toggle, Download if download) → DataTable → Pagination |
| **Create / Edit** | PageHeader (title, back link) → Form card (sections with headings) → sticky footer bar (`Batal`, `Simpan`) |
| **Show** | PageHeader (title, `Edit` / `Hapus` if permitted) → detail grid (label/value pairs) → tabs (Lampiran, Riwayat Aktivitas) |

### 3.1 DataTable
- **Data:** server-side pagination, sort, search and filters. The state lives in the URL query, so it survives reload and is shareable.
- **Search:** debounced 300ms; `per_page` options 10 / 25 / 50 / 100.
- **Look:** header row in uppercase label style (12px/500, muted, letter-spacing 0.04em) with a 1px ink rule below it; rows separated by 1px `--border`; no zebra stripes; the hovered row uses `--muted`.
- **Columns:** sortable headers show ▲▼; numbers align right, dates use `format`, booleans use `StatusBadge`.
- **Row actions:** a `⋯` dropdown (Lihat, Edit, Hapus) showing only permitted items. A row click opens Show if `view` is permitted.
- **Bulk delete:** the checkbox column appears only with `delete`. The bulk bar shows "N dipilih · Hapus".
- **Download:** the button applies the current filters.
  - At or below the threshold, the browser downloads the file directly.
  - Above it, a toast says "Ekspor diproses, cek Unduhan".
- **States:**
  - Loading: skeleton rows (no spinner over the table).
  - Empty with no filters: `EmptyState` with a create CTA.
  - Empty with filters: "Tidak ada hasil" + "Reset filter".
  - Error: inline alert + retry.

### 3.2 Forms
- **Fields:**
  - Each field has a label on top; required fields show `*`. Help text is muted below the field and the error text in red below that.
  - Field types: input, textarea, select, combobox, relation-select (async search, 20 results), date, datetime, switch, number (locale-aware), currency (Rupiah), file (FileUpload).
- **On submit:**
  - The button is disabled while saving.
  - Validation errors scroll to the first error, and an error summary appears at the top for long forms.
  - The form works with Enter (no accidental submits from comboboxes).
- **Unsaved changes:** leaving a dirty form asks for confirmation.
- **Stale update (409):** a dialog says "Data ini telah diubah oleh pengguna lain" with two choices: `Muat ulang` (discard) or `Salin perubahan saya` (copies the user's values to the clipboard before reloading).

### 3.3 Destructive actions
- A `ConfirmDialog` names the item: "Hapus user **Budi Santoso**?" The confirm button is red; the default focus is Cancel.
- Delete is a soft delete, so the success toast says "Dipindahkan ke Sampah". It has an `Urungkan` action for 8s, available only to Super Admin.

### 3.4 FileUpload
- **Input:** drag-drop or click; the accepted types and max size are shown under the drop zone.
- **During upload:** per-file progress; it can be cancelled.
- **File list:** icon, name, size and uploaded-by; download uses a signed URL. Delete requires `edit` on the parent.

  - Below them, a two-bar comparison of login success vs failed (ink vs `--chart-3`, never red: this is a chart, not a status).
- **"Aktivitas per Jenis" card:**
  - Counts with a 3px colored left marker for the five event groups (Dibuat, Diubah, Dihapus, Autentikasi, Lainnya; downloads fall under Lainnya and have their own stat), then one segmented horizontal bar.
  - Segment colors follow `--chart-1…5` in order. Yellow is the largest category.
- **"Aktivitas per Hari" card:**
  - Vertical bar chart in ink, a dotted horizontal grid, and day labels formatted `1 Okt`.
  - The hovered bar turns yellow and shows a tooltip card "412 aktivitas · 18 Okt 2026".
  - Ranges above 60 days group by week, and the labels show the week start.

**Event list (below the summary)**
- **Columns:** Waktu, User (name + level badge), Modul, Event (soft badge: Dibuat = success, Diubah = info, Dihapus = destructive, Login gagal = warning, other = neutral), Subjek (label + id), and a chevron.
- **Row detail drawer (right side, 480px):**
  - Header: event badge, user, time, IP address.
  - Body: `DiffTable` with Field, Sebelum, Sesudah columns. Changed values use soft destructive/success backgrounds; unchanged fields are hidden behind "Tampilkan semua".
  - Long JSON values are collapsed.

**States to show:** loading (skeleton tiles + skeleton bars + skeleton rows), an empty range ("Tidak ada aktivitas pada rentang ini"), a permission-limited view (no Unduh button), and the drawer open. Show the 375px layout: tiles stack 1 per row, the side column moves below the charts, and the daily chart scrolls horizontally inside its card.

### 4.4 Settings (SA only)
- **Tabs:** Umum (app name, favicon, logo 1:1, logo landscape), Kontak (telepon, WhatsApp, alamat, kode pos), Sosial Media (six platforms), Akses Situs (mode + message), Keamanan (session lifetime), Ekspor (threshold), Kesehatan (health status, Post-v1). Design spec §7.3 lists the keys.

### 4.5 Downloads
- **List columns:** File, Modul, Baris, Status (Diproses / Siap / Gagal / Kedaluwarsa), Dibuat, Kedaluwarsa.
- **Actions:** Unduh when the file is ready. A failed export shows its error message.

### 4.6 Health (SA, inside Settings)
- **Display:** a list of checks, each with a status dot (ok / warning / failed), a message and the last run time.
- **Action:** a "Jalankan ulang" button.

### 4.7 Auth screens
- Login, Forgot/Reset Password and Change Password use a centered card with the app logo and name from Settings. Change Password lives at `/account/password` (URL paths are English, UI text Indonesian), linked from the user menu; it replaces the starter kit's Settings → Security page.
- No sign-up page; accounts are created by an admin.

### 4.8 Beranda (Dashboard), reference-image layout
- **Header:** title "Beranda", a greeting line ("Selamat siang, Budi"), and a range control on the right (7 hari / 30 hari / 90 hari), followed by the 2px ink rule.
- **Grid:** 12 columns in the arrangement of the reference image:
  - Row 1: three `sm` stat tiles + one `sm` tall stat stack on the right.
  - Row 2: a `lg` segment card under the tiles (the stack continues beside it).
  - Row 3: a `full` bar chart.
  - Row 4: two `md` cards (recent activity table + another stat stack).
- **Widget card:** same card style as §1 (flat `--card`, 24px padding). The title (18px/600) has a 1px ink rule below it and a "Lihat semua ›" link on the right when the widget has a link.
- **Table widget:** at most 5 rows, compact (12px), no pagination, with a "Lihat semua ›" footer.
- **States to show:**
  - Every card loading (skeleton matching its type).
  - One card failed ("Gagal memuat" + "Coba lagi").
  - An empty page for a level with no widgets: an illustration-free `EmptyState` with module links.
  - The no-access page shown after login when the user has no permitted modules.
- **Responsive:** tablet and 375px layouts as in frontend-behavior §8.6.

### 4.9 Riwayat tab (on every Show page)
- A vertical timeline: a 6px dot colored by event badge, the event label, user name, and time on the right.
- Clicking a row expands an inline diff (field / sebelum / sesudah).
- A batch entry shows a muted "bagian dari 12 perubahan ›" link.
- The tab shows its count once loaded.
