# Test a module

Module tests live in `modules/{Name}/Tests` (generated by `make:module`) and run in the `Modules` suite. Use the static helpers in `Yuan\AdminCore\Testing\ModuleAssertions` (static, so PHPStan types them inside Pest closures):

- `ModuleAssertions::assertGuestRedirected('get', '/admin/{slug}')`
- `ModuleAssertions::assertForbiddenWithout('{slug}.edit', 'put', $uri, $data)` (signs in with every other permission of the module)
- `ModuleAssertions::actingAsLevelWith(['{slug}.view', '{slug}.edit'])` / `ModuleAssertions::actingAsSuperAdmin()`
- `ModuleAssertions::assertAudited($record, 'updated', masked: ['npwp'])`, `ModuleAssertions::assertNotVisibleToNonSuperAdmin($row)`
- `ModuleAssertions::assertScopedToUser({Name}::class, 'get', $uri)`: the route goes through `visibleTo()` with the signed-in user
- Widgets: `ModuleAssertions::assertWidgetHiddenWithout()`, `ModuleAssertions::assertWidgetUsesScope()`, `ModuleAssertions::assertWidgetWithinBudget()`

Every module covers: guest redirect; 403 without the permission for each action; success with it; required-field validation; download returns a file and writes an audit row (if declared); delete is soft and only Super Admin restores; create / update / delete audit events with masked fields masked; a stale update returns 409 (if `edit` is declared); the visibility scope.

Rules: factories and `RefreshDatabase`, never hardcoded IDs; HTTP calls through the `Pest\Laravel` functions (`get`, `post`…); Pest functions are global, so give helpers module-specific names (`kendaraanUser()`, not `user()`); never create permissions in tests (use the helpers); never weaken a test to get green. `tests/Feature/ContractTest.php` checks the whole module contract. Run `composer check`.
