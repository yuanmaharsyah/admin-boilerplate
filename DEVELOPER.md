## 1. What This Is (30-second version)

- A **Laravel 13 + Inertia 3 + React 19 + TypeScript** admin panel boilerplate (PHP 8.4+, MySQL 8).
- The reusable core is a Composer package **`yuanmaharsyah/admin-core`**. Each client project is a copy of **`skeleton/`** that requires the package.
- Every feature is a **module**: a folder with a `module.php`. Routes, menu, command palette and permissions are all derived from that file automatically.
- Access control: each user has exactly one **Level**. A level has **permissions** `{module}.{action}` (view, create, edit, delete, download, plus custom actions). Only Super Admin manages levels.
- Every change and security event is written to the **activity log** automatically (models via a trait, everything else via `Audit::record()`), with personal data masked. Audit rows can't be edited or deleted.
- **Beranda** is a widget dashboard: modules register widgets in `module.php`, and each user sees only the widgets they have permission for.
- PHP ↔ TS contracts are generated:
  - laravel-data → `generated.d.ts`.
  - Wayfinder → typed routes.

  Never hand-write prop types or URLs.

Read in this order and stop as soon as you have enough:

## 3. Architecture in One Picture

```
Request /admin/invoices?filter[status]=paid
  │
  ▼
web → auth → active → permission:invoices.view          (route middleware from ModuleRegistry)
  │
  ▼
InvoiceController@index
  ├─ Gate::authorize('viewAny', Invoice::class)          (policy; Gate::before passes Super Admin)
  ├─ Invoice::query()->visibleTo($user)                  (data-scope hook, no-op by default)
  │        ->dataTable($request)                          (HasDataTable: filter/sort/search/paginate)
  └─ Inertia::render('Invoice::Index', [
        'invoices' => PaginatedData::fromPaginator($page, InvoiceListItemData::class),   (keeps the query string)
     ])
  │
  ▼
HandleInertiaRequests adds shared props: AuthData, MenuGroupData[], AppData  (flash: native Inertia::flash(FlashData))
  │
  ▼
PageResolver → modules/Invoice/resources/js/pages/Index.tsx
  └─ <AdminLayout> <PageHeader/> <DataTable/> </AdminLayout>
       props typed by generated.d.ts, links built with Wayfinder
```

Writes follow the same path:
- The input `StoreInvoiceData` / `UpdateInvoiceData` validates.
- The policy authorizes.
- The controller saves inside `DB::transaction`; the model's `LogsModuleActivity` writes the audit row in the same transaction (masked, with request context).
- `PreventsStaleUpdates` checks the `lock_version` the form loaded on update.
- The controller redirects with flash.

## 4. Glossary

| Term | Meaning |
|---|---|
| **Module** | Folder with `module.php`; one feature. Two roots: core (package) and project (`modules/`) |
| **Slug** | Module id used in URL (`/admin/{slug}`), route names (`{slug}.index`) and permissions (`{slug}.view`) |
| **Action** | A permission verb declared in `module.php`: `view, create, edit, delete, download` or a custom single word |
| **Level** | A spatie Role. One per user. `is_protected` = Super Admin |
| **Super Admin (SA)** | Protected level. Passes all gates. The only one who manages Levels, the matrix, Settings, Trash and Health |
| **superadmin_only** | Module flag: no permissions generated, SA middleware, hidden from the matrix |
| **Data object** | A laravel-data class. Every prop and every input. Generates TS types |
| **Download** | Export of a list with its current filters (xlsx/csv). Queued above the threshold |
| **Eject** | Copy a core module into the project to modify it; it stops getting package updates |
| **Contract tests** | Tests that fail when the module contract or RBAC rules are broken (spec §9.1) |
| **Audit event** | One `activity_log` row. Name from the `AuditEvent` taxonomy or a declared custom action; `log_name` = module slug, `auth` or `system` |
| **Batch** | Audit rows sharing a `batch_uuid` because one operation changed many records |
| **Widget** | A class in `Widgets/` listed in `module.php`; one card on Beranda |

### R17. Build a list page · _Phase 06a_
1. Model: `implements DataTableModel`, `use HasDataTable, HasVisibilityScope`; an "own unit only" rule goes in `applyVisibility()`; override `dataTableSearch()` (columns), `dataTableSorts()`, `dataTableFilters()` (`DataTableFilterData` + `OptionData` options). Index every sort and filter column.
2. Controller `index(Request $request)`: `Gate::authorize('viewAny', …)` → `PaginatedData::fromPaginator(Model::query()->visibleTo($request->user())->with(…)->dataTable($request), …ListItemData::class)` and `'table' => Model::dataTableState($request)`.
3. Page: `<DataTable data state columns slug label itemLabel rowLabel rowActions bulkDelete empty />`. Column keys are typed against the row; pass `rowActions` items and `bulkDelete` only for permitted actions (`can()`).
4. Example: `skeleton/modules/Invoice` (demo module).

### R18. Delete and Trash · _Phase 06a_
1. Model uses `SoftDeletes` (and `HasDataTable`, which the Trash search needs).
2. Routes: `TrashController::routes(Model::class);` **before** any `{model}` wildcard route; `Route::delete('/', …bulkDestroy)` and `Route::delete('{model}', …destroy)->whereNumber(…)` with `permission:{slug}.delete`.
3. Controller: load with `->visibleTo($user)`, `Gate::authorize('delete', $model)` per row, then `Trash::delete($models, '{slug}')` (one transaction, one audit batch, toast with undo for Super Admin); bulk input is `SelectionData`.
4. Page: `ConfirmDialog` for a single row; the DataTable confirms bulk deletes itself. Super Admin gets a "Sampah" link to `trash()` in the page header.

### R19. Build a create / edit / show page · _Phase 06b_
1. Data: `Store{Name}Data` and `Update{Name}Data` (the same fields + `lock_version`), rules in `rules()`, Indonesian field names in `attributes()`. A relation is an `int` validated with `new VisibleRecord(Target::class)` (never `exists:`), so a user can only link records they may see; enums are PHP enums with `label()` / `options()`.
2. Migration: `$table->unsignedInteger('lock_version')->default(0);`. Model: `use PreventsStaleUpdates`, cast `lock_version` to integer and `protected $attributes = ['lock_version' => 0];`. Controller `update()`: load with `->visibleTo()`, authorize, `$model->updateUnlessStale($data->except('lock_version')->toArray(), $data->lock_version)`. Routes with a numeric `{model}` go in `Route::whereNumber('{model}')->group(…)`.
3. Page: `const { form, submit, stale, dirtyData, reload } = useAdminForm<Values>(…)`, a `<form noValidate onSubmit>` with the fields (from `components/{Name}Form.tsx`) and `<FormFooter>`; `<UnsavedChangesGuard when={form.isDirty && !form.processing}>`; edit pages add `<StaleUpdateDialog open={stale} dirtyData={dirtyData} onReload={reload}>`. Form state type: the store Data's fields, each nullable (`InvoiceFormValues`).
4. Relation: the target module has `GET lookup` (`permission:{slug}.view`) returning `LookupData` (≤ 20, `->visibleTo()`); the form uses `<RelationSelect lookupRoute={lookup} valueLabel={…}>`.
5. Show: `PageHeader` with Edit / Hapus by permission, `DetailGrid` in a card. Breadcrumbs from the controller (`BreadcrumbsData`). Riwayat tab: the model uses `HasActivityHistory`, the controller sends `'history' => ActivityHistory::prop($model, $request->user())`, the page adds a `Tabs` entry with `<ActivityHistory>` when `history !== null`.
6. Strings: the module's dictionaries (R20). Example: `skeleton/modules/Invoice`.

## 8. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Module missing from menu | Not enabled, no `view` permission, or cached definitions | `modules:clear`, check `module.php`, SA → Hak Akses |
| 403 even though the matrix is ticked | Permission cache or wrong slug | `permissions:sync`; check the route middleware slug |
| `GuardRailViolation` | Code tried to remove the last active Super Admin, change or delete the protected level, delete a level with users, or give a user a role/permission directly | Use `assignLevel()`; keep ≥1 active SA (`admin:create-superadmin`) |
| Every page redirects to "Ganti kata sandi" | The account has `must_change_password` (new account, or an admin reset its password) | Expected; change the password, or sign out |
| Logged out with "Sesi Anda telah berakhir" | The account was deactivated, or its level or password changed, after this session signed in (`users.session_version` moved on) | Expected; sign in again |
| Seeder fails in production with "Set ADMIN_SEED_PASSWORD" | No seed password in production | Set `ADMIN_SEED_PASSWORD`, or skip the seeder and run `admin:create-superadmin` |
| Page not found `X::Index` | Wrong name, wrong case, or Vite glob not rebuilt | The folder name = `name`, pages live in `resources/js/pages`, and the page name's case matches the file exactly; restart `composer dev` |
| `Invalid module definition in [...]` at boot | A `module.php` breaks a contract rule | The message names the file, the key and the rule; fix that key |
| A new or changed module doesn't show up | Module definitions are cached (`optimize` ran `modules:cache`) | `php artisan modules:clear` (or `modules:cache` again); `admin:doctor` reports a stale cache |
| TS error after a PHP change | Types not regenerated | `typescript:transform` + `wayfinder:generate` |
| A new Data class is missing from `generated.d.ts` | It lives outside the scanned directories (`app/`, module roots, core `src/`) | Move it, or add the directory in `TypeScriptTransformerServiceProvider` |
| `composer check` fails on generated diff ("Generated files are stale or untracked") | Generated files not committed, or new and untracked | Regenerate and commit |
| `check:generated`: "Generated files contain absolute paths" | A generator wrote a machine-specific path (e.g. Wayfinder through a symlink, `@see Users/…`) | Regenerate (`php artisan wayfinder:generate --with-form`; the package rewrites its own paths to `vendor/yuanmaharsyah/admin-core/…` after every run, also from the Vite plugin); if it persists, the path comes from a new source: fix that at the cause |
| `composer check` fails with "does not comply with psr-4 autoloading standard" | A folder's case (or a file's location) doesn't match its namespace; works on macOS, breaks on Linux | Rename the folder to match the namespace exactly (`git mv` in two steps for a case-only rename) |
| "Composer detected issues in your platform: … PHP >= 8.4.1" | CLI PHP is older than 8.4 | Switch the CLI to PHP 8.4 (your PHP version manager, or the `php` on your PATH) |
| Arch test "… is gone: remove it from tests/arch-exceptions.php" | A starter-kit file was replaced but its exception line stayed | Remove its line from `tests/arch-exceptions.php` (the single list, AGENTS.md §5) |
| PHPStan `adminCore.inertiaProps` / `adminCore.requestInput` | A controller passes an array/model/collection to Inertia, or reads `all()` / `validated()` / key-less `input()` | Wrap the value in a Data object; take a Data object as the action's parameter |
| Module `icon` rejected: "must be a lucide icon name" | Not a name in the installed lucide-react (case and spelling matter) | Pick a name from `resources/icons/lucide.json`; after upgrading lucide-react run `npm run icons` |
| Vite "failed to resolve import" for a file under `packages/admin-core` | The monorepo symlink: the package must resolve its imports from the skeleton's `node_modules` | Keep `resolve.preserveSymlinks: true` in `vite.config.ts`, and list the package in `admin-core.npm.json` |
| `test:built` fails with "Unable to locate file in Vite manifest" | A module page the build didn't pick up, usually a folder whose case differs from `resources/js/pages` (passes on macOS everywhere else) | Rename the folder to exactly `resources/js/pages` (`git mv` in two steps) |
| Browser tests fail with "Executable doesn't exist" / Playwright errors | Playwright's Chromium isn't downloaded on this machine | `npx playwright install chromium` in `skeleton/` (once per machine / CI image) |
| A list returns 400 | The URL has a `sort` or `filter[…]` the model doesn't declare (spatie query-builder) | Add it to `dataTableSorts()` / `dataTableFilters()`, or fix the link |
| `npm run build` fails in the Wayfinder plugin with a PHP version error | Vite's Wayfinder plugin runs `php artisan`; the CLI PHP is older than 8.4 | Switch the CLI to PHP 8.4 first |
| An arch rule doesn't fail when it should | Pest passes `expect([$a, $b])->not->toUse()` with a list, and whole-project checks skip autoload-dev and uninstalled classes | One namespace per expectation; use an `ArchRules` source scan for uninstalled classes |
| Skeleton tests fail with "Access denied … admin_boilerplate_test" | Test DB missing or DB user lacks rights on it | Grant the `.env` DB user rights on `admin_boilerplate_test`; `composer setup` creates it |
| Download never arrives | Queue worker not running | `admin:doctor`; supervisor status |
| Logo or favicon from Settings answers 404 | `public/storage` link missing | `php artisan storage:link`; `admin:doctor` checks it |
| `GoldenModulesTest` fails: "modules/Sample…/… differs from the stubs' output" | A stub changed (or a golden module was edited by hand) | Never edit the golden modules; after an intended stub change run `composer sample:regenerate` and commit the result |
| make:module: "no lookup route for the RelationSelect" | The `foreign(table)` target module has no `lookup` route | Add it to that module first (R19 step 4) |
| Public pages answer 503 / "Segera hadir" | Settings → Akses Situs is maintenance or coming soon | Settings → Akses Situs, or `php artisan admin:access open` |
| A user lands on "Belum ada akses" after sign-in | Their level has no `{slug}.view` of any menu module | SA → Levels → Hak Akses |
| A Beranda card shows "Gagal memuat" | Exception in that widget's `data()` (reported) | Fix the query; the other widgets are unaffected |
| An upload is refused although the extension is allowed | The `mimes` rule checks the file's content, not its name | Upload a real file of that type |
| A test with `X-Inertia: true` gets 409 | Inertia's asset-version check, not your code | Also send `X-Inertia-Version` (the middleware's `version()`) |
| "Data changed by someone else" | Stale-update protection (expected) | Reload; this is a feature |
| Boot error "duplicate slug" | Project module collides with core | Rename the slug, or eject the core module |
| A change doesn't appear in the Log Aktivitas | Model lacks `LogsModuleActivity`, or only non-fillable fields changed | Add the trait; check `$fillable` |
| `ImmutableAuditException` | Code tried to update or delete an activity row | Remove that code; audit rows are append-only |
| "Unknown audit event" | `Audit::record()` with a name not in the taxonomy and not a declared action | Use an `AuditEvent` case or declare the action |
| User sees other units' numbers on Beranda | Widget forgot `visibleTo()` or uses `sharedCache()` wrongly | Add the scope; set `sharedCache()` false |
